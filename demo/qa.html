Surfaces & scale

interactive-tokens.css

The press mechanism. A surface carries the themed fill and border across rest, hover and press; a scale carries the transform. Pair one of each — and put the pair on a <button> or an <a>, because a tappable <div> is a target nobody can reach. Hover them, and tab through them.

Fill — solid, darkens on press
Border — outlined, fills lightly on hover

Known issues

docs/roadmap.md § gap 8 · npm run check:a11y

Measured by axe-core across every sheet in both modes, then split by what they actually are. Turn on Known issues above to see each one marked where it renders.

32 · componentsUnambiguously wrong. .btn-destructive 4.17, .input-message on error 4.00, stat-table headers 2.84.
28 · disabledWCAG 1.4.3 exempts disabled controls, so these are conformance-neutral. axe flags them anyway.
22 · brand as text1.07–2.50. A brand colour is picked to be a brand, not body copy.
21 · status as text.text-warning 2.76, .text-info 4.23 — the second is one nudge from passing.

None of these are fixed, deliberately: every one needs a token value decided, which is a design call rather than a refactor. npm run check:themes did not catch any of them because it checks three pairs — two button types out of nine.

What this page is. Every component family with its variants, plus three composed screens. It is not exhaustive at the utility level — the 300-odd spacing, grid and visibility utilities are listed by name in docs/css-api.md and shown one by one across the thirteen sheets in demo/, which this page does not replace.

How to trust it. Nothing here is a mockup: the page loads the real css/crnl.css and the real fonts, so what you are looking at is the system running. Every class used is in docs/css-api.json — npm run lint fails on an invented one.

Placeholder copy throughout. No name, price or date here comes from anywhere real (RULES §6).
